## 1. 背景与目标

### 1.1 现状问题

现在语音对话只能"说"，不能"做"。用户说「关闭对话」，模型只能回一句"好呀，你自己点一下吧"——真正的关闭动作仍要用户手动点（单击桌宠 / 关页面）。桌宠是"陪聊"而不是"能动手的桌宠"。

### 1.2 目标

用 DeepSeek 的 function calling（`tools`），让模型在对话中调用 **5 个本地工具**，由 App 侧执行：

| 目标 | 可度量的判定 |
| --- | --- |
| 说一句就能关对话 | 说「关闭对话」→ 3 秒内停止倾听与播报，桌宠仍在屏幕上 |
| 能开应用、能记账式记忆、能定时、能藏自己 | 5 个工具各至少 1 条真机验收通过（见 §7） |
| 不误伤 | 「关闭微信」类表述 0 次误触发 `close_conversation`（§5 反例表全过） |
| 不加新依赖 | 无新增三方库、无服务器、无新增危险权限（`SCHEDULE_EXACT_ALARM` 见开放问题 4） |
| 不破坏现有链路 | 未开工具调用时，语音对话行为与现在完全一致（可回滚开关） |

### 1.3 非目标（摘要）

任意 shell / 发短信 / 转账 / 读通知内容等一律不做，详见 §8。

## 2. 现状事实与硬约束（读代码核对）

这一节是实现者必须遵守的既有事实，不是建议。

| # | 事实 | 位置 | 对需求的约束 |
| --- | --- | --- | --- |
| F1 | `SseClient.stream` 的请求体只有 `model/messages/stream/temperature/max_tokens`，**没有** `tools` / `tool_choice` | `chat/SseClient.kt:62-70` | 必须扩展请求体；属本需求的必要改动 |
| F2 | 解析器只取 `choices[0].delta.content`，**丢弃** `reasoning_content`，不认 `delta.tool_calls` | `chat/SseClient.kt:226-232` | 工具调用需要独立通道，不能塞进正文 |
| F3 | `ChatClient.stream` 把回调适配成 `Flow<String>` | `voice/chat/ChatClient.kt` | 正文流与工具调用流必须分开，否则 TTS 会念 JSON |
| F4 | `VoiceLoop.oneTurn` 对每个 delta 做 `replace("null"/"none"/"undefined")` 清洗 | `voice/core/VoiceLoop.kt:468-476` | **工具参数绝不能过这个清洗器**，否则 JSON 被破坏 |
| F5 | 一轮 = 一次"模型回答 → 分句 → TTS → 播放"，没有第二跳 | `voice/core/VoiceLoop.kt:398-513` | 工具调用要加"模型→工具→模型"第二跳，必须有轮次上限 |
| F6 | `stop()` 会 `cancel` 协程 + `player.abort()` + 取消在途 TTS | `voice/core/VoiceLoop.kt:197-208` | `close_conversation` 若立即 `stop()`，会把"我关了啊"这句掐掉 |
| F7 | 语音入口是进程级单例 `VoiceRuntime`，多开时 `ensureStarted` 复用同一个 loop | `voice/core/VoiceRuntime.kt:40-48` | 工具执行的目标桌宠实例需显式解析，不能"就近取" |
| F8 | 桌宠只有 `hide`/`show` 两条 START 指令可控制隐藏，走 `setHidden`（= 灵动岛单击同一条路径） | `pet/PetOverlayService.kt:627-628, 944-953` | `pet_visibility` 复用该通道，不要新写窗口逻辑 |
| F9 | 服务存活期间，隐藏后**唯一**恢复入口是灵动岛（`DynamicIsland` 的 show/hide）。打开 App 不会恢复：`ensureRunning` 在 `container != null` 时直接早退，不重建窗口、也不读 `petHidden` | `pet/DynamicIsland.kt:175`, `pet/PetOverlayService.kt:204-215, 674` | 灵动岛未开时隐藏 = 桌宠"消失且叫不回来"，必须拒绝或先给恢复入口 |
| F10 | 快捷启动列表 `quick_launch_apps`（内容形如 `pkg\|label`）已存在，启动方式是 `getLaunchIntentForPackage` | `data/PetConfig.kt:174`, `pet/PetMenu.kt:274-279` | `open_app` 的白名单直接用它，不另建体系 |
| F11 | 记忆是本地 JSON：`voice_memory.json`，`MemoryStore.upsert` 自带去重/近似合并，`normalize` 后 <4 字拒收，容量 300 | `voice/memory/MemoryCore.kt:141-172, 257` | `remember` 的文本长度下限与去重语义对齐现有实现 |
| F12 | 记忆自动抽取是每轮异步跑的（`rememberAsync`），与工具无关 | `voice/core/VoiceLoop.kt:494-504` | `remember` 解决"用户明确要求记住"的确定性，不替代自动抽取 |
| F13 | 主动开口（`nudge`）与自言自语走一次性短请求，没有用户明确指令 | `voice/core/VoiceLoop.kt:336-369` | **这两条路径绝不带 tools** |
| F14 | 语音测试页是传统 View，设置页多为 Compose | `voice/VoiceLoopActivity.kt`, `voice/ui/PetSettingsActivity.kt` | 新增开关按页面现有技术栈放置，不混用 |
| F15 | 当前默认模型是 `deepseek-chat`；官方 API 文档当前列出的模型为 `deepseek-flash` / `deepseek-v4-pro`（2026-11 查证） | `chat/ChatConfigFactory.kt:21` | 模型是否支持 tools 由所选模型决定，见开放问题 9 |

### 2.1 接口层约束（DeepSeek Tool Calls，2026-11 官方文档）

| 项 | 事实 | 对本需求的影响 |
| --- | --- | --- |
| 工具定义 | `tools[].type` 只能是 `function`；`name` 限 `a-zA-Z0-9_-`、≤128 字符 | 5 个工具名全部合规（下划线） |
| `tool_choice` | `none`/`auto`/`required`/指定函数；**思考模式下 `required` 与指定函数返回 400** | 只使用 `auto`（默认值），不要依赖 `required` |
| 思考模式 | 请求不传 `thinking`/`reasoning_effort` 时**默认开启**思考 | 工具轮延迟会明显变长，见开放问题 9 |
| `strict` 模式 | Beta，且需要 `base_url=https://api.deepseek.com/beta` | 本项目 baseUrl 用户可改，**不依赖 strict**；参数校验必须在 App 侧做 |
| 工具结果回传 | `{"role":"tool","tool_call_id":"...","content":"..."}` | 结果必须是紧凑 JSON 字符串，且不能过 F4 的清洗器 |
| 参数可靠性 | 官方明示"模型不保证参数合法、可能编造 schema 之外的字段" | 每个工具都必须校验 + 有兜底文案 |

## 4. 工具清单

### 4.0 总览

| name | 一句话描述 | 副作用等级 | 幂等 | 需要权限 | 调用前置 |
| --- | --- | --- | --- | --- | --- |
| `close_conversation` | 结束当前语音对话，桌宠留在屏幕上 | L2 | 是 | 无 | 语音对话进行中 |
| `open_app` | 打开白名单里的一个应用 | L2 | 是（重复=切前台） | 无（`QUERY_ALL_PACKAGES` 已声明） | 白名单非空 |
| `set_timer` | 设置一个到点提醒的计时器 | L2 | 否（每次新建） | 通知（已声明）；精确闹钟见 OQ-4 | 计时器 < 5 个 |
| `remember` | 把一条关于用户的事实写进长期记忆 | L1 | 是 | 无 | 记忆未被用户清空锁定 |
| `pet_visibility` | 显示/隐藏桌宠本体 | L1 | 是 | 悬浮窗（已有） | 有存活实例；隐藏时需恢复入口 |

副作用等级定义：

| 等级 | 含义 | 本版本是否出现 |
| --- | --- | --- |
| L0 | 只读，无任何状态变化 | 否 |
| L1 | 只改本地状态/本地数据，用户可自行撤销 | 是（`remember`、`pet_visibility`） |
| L2 | 打断用户当前上下文（停播报、切前台、未来某刻主动发声） | 是（其余 3 个） |
| L3 | 不可逆或对外产生后果（发消息、下单、支付、删除数据） | **禁止出现** |

### 4.1 `close_conversation`

| 字段 | 内容 |
| --- | --- |
| name | `close_conversation` |
| 一句话描述 | 结束当前语音对话：停止倾听、停止合成与播报，桌宠本身不动、不退出 |
| 参数 | 无参数（空对象） |
| 成功返回 | `{"ok":true,"already":false}`（`already:true` = 本来就没在对话，仍算成功） |
| 失败返回 | `{"ok":false,"code":"not_in_voice_mode","retryable":false}` |
| 幂等性 | **是**。重复调用返回 `ok:true, already:true`，不报错、不重复播报 |
| 副作用等级 | L2（中断当前播报/识别，麦克风释放；不退出前台服务、不隐藏桌宠） |
| 时序约束 | **先说完最后一句再停**：允许本轮 TTS 播完（≤3 秒），再执行 `stop()`；不得先 `stop()` 导致半句被掐（F6） |
| 权限/边界 | 不关浮动对话窗、不关语音页、不改设置、不清历史与记忆 |

```json
{
  "type": "function",
  "function": {
    "name": "close_conversation",
    "description": "结束当前语音对话（停止倾听和说话）。仅当用户明确要求结束/关闭这次对话时调用。用户要求关闭其他应用、或只是让你别念了之外的其他操作时不要调用。",
    "parameters": { "type": "object", "properties": {}, "additionalProperties": false }
  }
}
```

### 4.2 `open_app`

| 字段 | 内容 |
| --- | --- |
| name | `open_app` |
| 一句话描述 | 打开用户「快捷启动」清单里的一个应用（切到前台） |
| 参数 | `app`（必填，应用名或包名，取值必须来自 system 提示里给出的可用清单） |
| 成功返回 | `{"ok":true,"app":"微信","pkg":"com.tencent.mm"}` |
| 失败返回 | `{"ok":false,"code":"app_not_allowed"}` / `app_not_found` / `launch_blocked`，均 `retryable:false` |
| 幂等性 | **是**（已在前台时再调用只等于再切一次前台，不产生叠加副作用） |
| 副作用等级 | L2（跨 App 跳转，会打断用户当前界面） |
| 白名单 | 只允许 `quick_launch_apps` 里的条目（F10）；空清单时**不注册该工具**（不给模型这个选项，而不是让它撞墙） |
| 匹配规则 | 先精确匹配 label，再匹配 pkg，最后忽略大小写/空格；命中多个 → 返回 `app_not_found` 让模型反问，**不猜** |
| 边界 | 不传 intent 参数、不带 URL、不打开系统设置页、不"顺手"关闭任何应用 |

```json
{
  "type": "function",
  "function": {
    "name": "open_app",
    "description": "打开用户快捷启动清单里的应用。app 必须是清单中出现的名字或包名，不要编造；清单里没有的应用一律不要尝试。",
    "parameters": {
      "type": "object",
      "properties": {
        "app": { "type": "string", "description": "应用显示名或包名，必须来自可用应用清单" }
      },
      "required": ["app"],
      "additionalProperties": false
    }
  }
}
```

### 4.3 `set_timer`

| 字段 | 内容 |
| --- | --- |
| name | `set_timer` |
| 一句话描述 | 设置一个到点提醒的计时器（到点由桌宠出声/气泡提醒） |
| 参数 | `duration_sec`（必填，整数 1–86400）、`label`（可选，≤20 字，如"关火"） |
| 成功返回 | `{"ok":true,"timer_id":"t-3f2a","fire_at":1762300000000}` |
| 失败返回 | `{"ok":false,"code":"invalid_duration"}` / `too_many_timers` / `service_unavailable`，均 `retryable:false` |
| 幂等性 | **否**。每次调用新建一个计时器；同一句里重复调用视为用户要两个（上限 5 个，超出返回 `too_many_timers`，不静默替换） |
| 副作用等级 | L2（未来某刻主动发声，打断用户） |
| 到点行为 | TTS 一句 + 气泡（"十分钟到啦"），并弹通知；**不**改系统闹钟、**不**响铃绕过静音 |
| 生命周期 | 仅在前台服务存活期间有效；进程被杀则失效，**本版本不承诺跨进程/重启存活**。取消方式：说「取消计时」不在本期（OQ-4） |
| 边界 | 不设重复提醒、不做日历、不做时段解析（"明早八点"→ 需换算成秒，模型算错就拒收，不做智能纠正） |

```json
{
  "type": "function",
  "function": {
    "name": "set_timer",
    "description": "设置一个一次性计时器，到点提醒用户。duration_sec 是最长 24 小时的秒数；用户说几点几分时请自行换算成秒数。不能设重复提醒。",
    "parameters": {
      "type": "object",
      "properties": {
        "duration_sec": { "type": "integer", "minimum": 1, "maximum": 86400, "description": "多少秒后提醒" },
        "label": { "type": "string", "description": "可选，提醒事项，如 关火、开会，最多 20 字" }
      },
      "required": ["duration_sec"],
      "additionalProperties": false
    }
  }
}
```

### 4.4 `remember`

| 字段 | 内容 |
| --- | --- |
| name | `remember` |
| 一句话描述 | 把一条关于用户的稳定信息写进长期记忆，下次可被检索到 |
| 参数 | `text`（必填，4–60 字，写事实不写寒暄）、`type`（可选，`preference`/`habit`/`fact`/`event`，默认 `fact`）、`keywords`（可选，≤6 个） |
| 成功返回 | `{"ok":true,"action":"created","id":"a1b2c3"}`（`action` 取值：`created` / `updated` / `unchanged`） |
| 失败返回 | `{"ok":false,"code":"text_too_short"}` / `sensitive_blocked` / `store_failed` |
| 幂等性 | **是**（F11：归一化后同文本只刷 `updatedAt`，`action=unchanged`） |
| 副作用等级 | L1（写 `voice_memory.json`，用户可在记忆页查看/清空） |
| 拒绝写入 | 密码、验证码、银行卡/身份证号、API Key 一律 `sensitive_blocked`（本地正则初筛，不依赖模型自觉） |
| 边界 | 不删除、不修改已有记忆（本期只增不改）；不与自动抽取抢写（自动抽取照旧，见 F12） |

```json
{
  "type": "function",
  "function": {
    "name": "remember",
    "description": "用户明确要求你记住某件事时调用。只写用户本人的稳定偏好、习惯、事实或有日期的计划；不写寒暄、不写你自己说过的话、不写密码和证件号。",
    "parameters": {
      "type": "object",
      "properties": {
        "text": { "type": "string", "description": "一条事实，4 到 60 字，以“用户”或具体信息开头" },
        "type": { "type": "string", "enum": ["preference", "habit", "fact", "event"] },
        "keywords": { "type": "array", "items": { "type": "string" }, "description": "最多 6 个检索关键词" }
      },
      "required": ["text"],
      "additionalProperties": false
    }
  }
}
```

### 4.5 `pet_visibility`

| 字段 | 内容 |
| --- | --- |
| name | `pet_visibility` |
| 一句话描述 | 显示或隐藏桌宠本体（服务照常运行） |
| 参数 | `visible`（必填，布尔） |
| 成功返回 | `{"ok":true,"visible":false}` |
| 失败返回 | `{"ok":false,"code":"no_pet"}` / `no_recovery_entry` / `overlay_permission_missing` |
| 幂等性 | **是**（状态式参数，重复调用同值无变化） |
| 副作用等级 | L1（仅悬浮窗可见性；不停服务、不停语音、不改配置持久化） |
| 前置校验 | 隐藏时若灵动岛未开启（F9）→ 返回 `no_recovery_entry`，**不执行**（避免桌宠"消失且叫不回来"） |
| 语音中的行为 | 隐藏时**保留**语音状态胶囊（用户必须仍能看到"在听"）；若对话未进行，则连胶囊一起收起 |
| 边界 | 不做缩放/移动/换皮肤；不隐藏通知栏常驻通知 |

```json
{
  "type": "function",
  "function": {
    "name": "pet_visibility",
    "description": "显示或隐藏桌宠。visible=false 时桌宠从屏幕上消失但仍在运行；只有用户明确说“躲起来/藏起来/出来吧”时才调用。",
    "parameters": {
      "type": "object",
      "properties": { "visible": { "type": "boolean", "description": "true 显示，false 隐藏" } },
      "required": ["visible"],
      "additionalProperties": false
    }
  }
}
```

### 4.6 system 提示里必须给模型的运行时上下文

| 上下文 | 内容 | 为什么不放在工具描述里 |
| --- | --- | --- |
| 可用应用清单 | 当前 `quick_launch_apps` 的 label 列表（去重、最多 20 个） | 清单是用户配置，随每轮变化 |
| 当前对话状态 | 是否在语音对话中、桌宠是否可见 | `close_conversation` / `pet_visibility` 的合法性判断依据 |
| 计时器现状 | 已有几个、最近一个的剩余时间 | 避免"闹钟太多"被模型无视 |

## 5. 触发与不触发规则

### 5.1 触发前置条件（全部满足才把 tools 放进请求）

| # | 条件 | 不满足时 |
| --- | --- | --- |
| P1 | 工具调用总开关开启（US-8，默认开） | 请求不带 `tools`，行为与现在一致 |
| P2 | 本轮是**用户主动发起的对话轮**（`oneTurn`，含文字输入） | `nudge`/自言自语/记忆抽取/整理一律不带 tools（F13） |
| P3 | 当前模型支持 tools（模型名匹配，见 OQ-9） | 不带 tools，日志留痕一次 |
| P4 | 输入是**最终识别结果**，不是 ASR 中间结果（partial） | partial 永不触发，防"关闭对…"提前执行 |
| P5 | 单轮工具往返次数 < 3 | 第 3 次后强制收尾，不再给 tools |

### 5.2 该触发（正例）

| 用户说法（ASR 文本） | 工具 | 说明 |
| --- | --- | --- |
| 关闭对话 / 关掉对话 / 结束对话 / 不聊了 / 先这样吧 / 退下吧 | `close_conversation` | 明确指向"这次对话" |
| 别念了 / 停一下 / 别说了 | `close_conversation` | 本期无"暂停"，最接近的行为是关闭；应答需说明是关掉（OQ-1） |
| 打开微信 / 帮我开下支付宝 / 开个抖音 | `open_app` | 目标在白名单内 |
| 十分钟后叫我 / 定个二十五分钟计时 / 提醒我三点关火 | `set_timer` | 时间已可换算成秒 |
| 记住我周三下午有课 / 记一下我不吃香菜 | `remember` | 明确要求"记住" |
| 你先躲起来 / 藏起来吧 | `pet_visibility{visible:false}` | 有恢复入口时 |
| 出来吧 / 你回来 | `pet_visibility{visible:true}` | — |
| 打开微信然后关掉对话 | `open_app` + `close_conversation`（按此顺序） | 多意图：先跳转，最后关（关了就没人说话了） |

### 5.3 绝不该触发（反例）

| 用户说法 | 期望行为 | 为什么 |
| --- | --- | --- |
| **关闭微信** / 把抖音关了 / 退出淘宝 | 不调任何工具，回答"这个我关不了" | 对象是**别的 App**，不是对话；`close_conversation` 绝不能兜底 |
| 关掉闹钟 / 取消刚才那个计时 | 不调 `set_timer`（本期无取消），回答"我现在还不会取消" | 没有对应工具就不能假装有 |
| 关掉音乐 / 调小音量 / 关掉蓝牙 | 不调任何工具，回答做不到 | 系统级操作不在能力内 |
| 打开手电筒 / 打开设置 / 打开相机 | 不调 `open_app`（不在白名单就不是它的活） | 白名单是唯一合法来源 |
| 他说"关闭对话"是什么意思 | 不触发，只解释 | 引用/转述，不是指令 |
| 先别关 / 别关闭对话 | 不触发 | 否定句 |
| 等我说关闭对话的时候你就关 | 不触发 | 假设/将来/规则设定 |
| 我昨天说关闭对话它就没反应 | 不触发 | 叙述过去，非指令 |
| 帮我记住这句话：关闭对话 | 只调 `remember`，**不调** `close_conversation` | 引号内是被记录的内容，不是命令 |
| 关闭对话框 | 不触发，反问一句"关哪个？" | 歧义（可能指别的 App 的弹窗） |
| 关上窗帘 / 关门 / 挂了 | 不触发 | 同音/生活用语，无对应动作 |
| 关闭对话（第 2 次，3 秒内） | 第二次返回 `already:true`，不再播报"好" | 幂等 + 防重复应答 |
| （主动开口 / 自言自语时）"我该干点什么" | 不触发任何工具 | 无用户指令（P2） |

### 5.4 判定优先级（模型与 App 双层都要遵守）

1. **先看是否"非指令"**：否定、引用、假设、过去叙述、解释请求 → 一律不执行（5.3 前 6 行）。
2. **再看动作对象**：对象是"对话/桌宠/记忆/计时"→ 可以命中本期工具；对象是**别的 App 或系统**→ 只回答，**绝不降级**成 `close_conversation`。
3. **再看参数是否可确定**：`open_app` 命中不到唯一应用、`set_timer` 时间无法换算成秒 → 不猜，反问一句。
4. **多意图**：按用户说的顺序执行，最多 2 个；`close_conversation` 永远排最后。
5. **拿不准时**：不执行，问一句"要关掉对话吗？"（疑问句，不加工具调用），用户确认后再执行。

### 5.5 硬规则（实现侧不可协商）

| 规则 | 原因 |
| --- | --- |
| 只有最终 ASR 文本能进模型并触发工具 | partial 会让"关闭对…"提前执行 |
| 工具失败由 App 兜底文案，禁止模型自行解释失败原因 | 模型会编"权限不足/网络问题" |
| 工具执行成功但模型没说 → App 补一句结果（气泡即可） | 用户要能确认"真做了" |
| 模型说做了但工具没成功 → App 追加纠正（"其实没做成"） | 不许出现"假成功" |
| 同轮同工具同名同参只执行一次 | 防重复开 App / 重复计时 |
| 执行 `close_conversation` 后本轮不再接工具 | 链路已停，再调必然失败 |

## 6. 失败语义与用户可见文案

### 6.1 三类失败要分开处理

| 类别 | 例子 | 处理原则 |
| --- | --- | --- |
| 模型层失败 | 网络断、401、超时、模型不支持 tools | 沿用现有 `VoiceEvent.Error` 通道，**不进**工具文案表 |
| 参数层失败 | `duration_sec=0`、`app` 不在清单、`text` 太短 | 不执行，把 `{ok:false,code}` 回给模型让它改口；同一参数只允许纠正 1 次 |
| 执行层失败 | 启动被系统拦、写记忆失败、隐藏无恢复入口 | 执行失败 → 硬编码文案（下表），**不再让模型自由发挥** |

### 6.2 文案表（≤15 字，口语化）

| 场景 | 触发条件 | 文案（TTS + 气泡） |
| --- | --- | --- |
| 关对话成功 | `close_conversation` ok | 好，那我先歇着 |
| 已经关了 | `already:true` | （不说话，仅日志） |
| 关对话失败 | `not_in_voice_mode` | 这会儿没在聊呀 |
| 开 App 成功 | `open_app` ok | 给你打开了 |
| App 不在清单 | `app_not_allowed` | 这个应用我还不认识 |
| 找不到/无入口 | `app_not_found` | 手机上没找到它 |
| 启动被拦 | `launch_blocked` | 系统不让我开它 |
| 计时成功 | `set_timer` ok | 好，到点喊你 |
| 时间不合法 | `invalid_duration` | 这个时间我没算明白 |
| 计时器满 | `too_many_timers` | 闹钟有点多了 |
| 记忆成功 | `remember` ok | 记住啦 |
| 记忆重复 | `unchanged` | 这个我记着呢 |
| 记忆太短 | `text_too_short` | 太短了，说全一点 |
| 记忆被拒 | `sensitive_blocked` | 这个我不记 |
| 记忆写失败 | `store_failed` | 这次没记住 |
| 隐藏成功 | `visible:false` | 我先躲起来 |
| 显示成功 | `visible:true` | 我回来啦 |
| 无恢复入口 | `no_recovery_entry` | 先开灵动岛再藏我 |
| 无悬浮窗权限 | `overlay_permission_missing` | 先给我悬浮窗权限 |
| 不是它干的 | 模型自述成功但工具失败 | 其实没做成 |
| 轮次超限 | 3 次往返后仍在调工具 | 我先停一下 |
| 通用失败 | 未归类的执行异常 | 这个没弄成 |

**文案规则**

1. 上表文案**由 App 硬编码**，模型不得改写、不得追加解释。
2. 成功应答由模型说，但限制 ≤20 字、单句、不带 JSON/字段名；超长由 App 截断。
3. 同一个失败码 10 秒内只念一次，后续只出气泡（防刷屏，对齐现有 ASR 去重策略）。
4. 失败文案**不念技术细节**（不出现 HTTP 码、异常类名、包名）。
5. `close_conversation` 的成功文案必须先念完再停（F6）；来不及念完则跳过文案直接停，不报错。

## 7. 验收标准（真机可勾选）

前置：真机 1 台 Android 12+（机型待填）、已配置 DeepSeek Key、麦克风/悬浮窗/通知权限已给、快捷启动里至少配 3 个应用。

### AC-1 开关与回归

- [ ] AC-1.1 工具调用开关关闭时，语音对话行为与 4.3.7 完全一致（不出现任何工具调用日志）
- [ ] AC-1.2 开关打开后，普通闲聊（"今天好累"）**不产生任何工具调用**，回复内容与关闭时无肉眼差异
- [ ] AC-1.3 主动开口（沉默 30s 后它自己说话）期间不出现工具调用
- [ ] AC-1.4 开关可即时生效，不需要重启服务（改完下一轮就变）

### AC-2 关闭对话

- [ ] AC-2.1 三击进入语音对话后说「关闭对话」→ 3 秒内停止倾听与播报，状态胶囊消失，**桌宠仍在屏幕上**
- [ ] AC-2.2 关闭前能听到一句完整收尾（不是半句被掐）
- [ ] AC-2.3 关闭后单击/三击桌宠行为正常（三击可重新进入对话）
- [ ] AC-2.4 连说两遍「关闭对话」→ 第二次不重复播报、不报错、日志显示 `already`
- [ ] AC-2.5 在**没有**对话时对桌宠说"关闭对话"（例如在语音页手动触发）→ 文案"这会儿没在聊呀"

### AC-3 打开应用

- [ ] AC-3.1 说「打开微信」（在白名单）→ 微信被切到前台，桌宠说"给你打开了"
- [ ] AC-3.2 说「打开淘宝」（**不在**白名单但已安装）→ 不打开，说"这个应用我还不认识"
- [ ] AC-3.3 说「打开一个不存在的应用」→ 不崩溃，说"手机上没找到它"
- [ ] AC-3.4 白名单为空时，说"打开微信"→ 模型不会尝试调工具，回答落回普通对话
- [ ] AC-3.5 说「打开微信然后关掉对话」→ 微信在前台，对话已关闭，顺序正确

### AC-4 计时

- [ ] AC-4.1 说「十秒后叫我」→ 10 秒左右听到提醒 + 看到气泡 + 通知栏有通知
- [ ] AC-4.2 说「二十五分钟后叫我」→ 返回的 `fire_at` 与当前时间差 ≈ 1500 秒（误差 ≤5 秒）
- [ ] AC-4.3 连设 5 个后设第 6 个 → 说"闹钟有点多了"，不静默覆盖
- [ ] AC-4.4 说「零秒后叫我」→ 拒收，说"这个时间我没算明白"
- [ ] AC-4.5 计时期间杀掉进程 → 到点不响（符合本期"不承诺跨进程"，文档需一致）

### AC-5 记忆

- [ ] AC-5.1 说「记住我周三下午有课」→ 记忆页出现该条（类型 preference/habit 之一）
- [ ] AC-5.2 再说同一句 → 条数不增加，日志 `unchanged`
- [ ] AC-5.3 说「记住我的银行卡号是 6222…」→ 拒绝，说"这个我不记"，记忆页无新增
- [ ] AC-5.4 清空记忆后再触发一次 `remember` → 能正常写入（不被清空动作锁死）

### AC-6 桌宠显隐

- [ ] AC-6.1 灵动岛开启时说「你先躲起来」→ 桌宠消失、胶囊消失、服务仍在（通知栏可见）
- [ ] AC-6.2 隐藏后点灵动岛 → 桌宠回来
- [ ] AC-6.3 灵动岛**关闭**时说「你先躲起来」→ 拒绝执行，说"先开灵动岛再藏我"，桌宠不消失
- [ ] AC-6.4 对话进行中说「你先躲起来」→ 桌宠消失但**状态胶囊仍在**（能看出它还在听）
- [ ] AC-6.5 隐藏后说「出来吧」→ 桌宠恢复显示

### AC-7 误触发（最关键）

- [ ] AC-7.1 说「关闭微信」→ 微信**不被关**、对话**不被关**，回答"这个我关不了"
- [ ] AC-7.2 说「关掉音乐」/「调小音量」/「打开手电筒」→ 均不执行，回答做不到
- [ ] AC-7.3 说「他说"关闭对话"是什么意思」→ 只解释，对话不关
- [ ] AC-7.4 说「先别关」→ 对话继续
- [ ] AC-7.5 说「帮我记住这句话：关闭对话」→ 只有记忆新增，对话不关
- [ ] AC-7.6 说「关闭对话框」→ 不执行，反问关哪个
- [ ] AC-7.7 ASR 只识别出半句「关闭对…」时（说一半停住）→ 不执行任何工具

### AC-8 性能与体验

- [ ] AC-8.1 带工具的单轮（"打开微信"）从说完到听见应答 ≤6 秒（4G 网络，工具往返 1 次）
- [ ] AC-8.2 工具执行期间不出现"JSON/字段名/包名被念出来"（听一遍完整回复确认）
- [ ] AC-8.3 工具失败时用户能听到中文口语文案，且 ≤15 字（人工数一遍）
- [ ] AC-8.4 单轮最多 3 次工具往返；制造死循环（连续要求"再开一次"）时不卡死、能收尾

### AC-9 隐私与安全

- [ ] AC-9.1 说「读一下我的通知」/「看看我的相册」/「删掉我的记忆」→ 全部拒绝
- [ ] AC-9.2 说「帮我转账」「发短信给妈妈」→ 拒绝，不产生任何系统跳转
- [ ] AC-9.3 logcat 中工具调用日志只含工具名、参数摘要（≤80 字）、耗时、结果码，**不含** API Key、完整记忆文本
- [ ] AC-9.4 关闭工具调用开关后，请求体里不再出现 `tools` 字段（抓包或日志确认）

## 8. 非目标（明确不做）

| 不做 | 原因 |
| --- | --- |
| 任意 shell / 执行命令 / 读写任意文件 | 越权，且违反边界要求 |
| 发短信、打电话、发微信消息、读聊天记录 | 对外产生后果，属 L3 |
| 转账、支付、下单、扫码 | 同上，且不可撤销 |
| 读通知内容（`PetNotificationListener` 已有能力但不暴露给工具） | 隐私敏感，一期不开 |
| 读通讯录、相册、剪贴板、日历 | 与"陪聊"无关，扩大攻击面 |
| 关闭/控制**其他 App**、改系统设置、调音量/亮度 | 需无障碍或系统权限，误触代价高 |
| 后台自主任务链（"帮我盯着…"）、跨会话长期计划 | 需要有服务器与调度，本期不做 |
| 多步自主 Agent 循环（无上限的工具链） | 一期只允许 ≤3 次往返 |
| 给第三方 App 注册工具（复用 `AgentEventBus`） | 与本期目标无关，另立需求 |
| 语音唤醒（"小肥鱼"）后直接执行工具 | 唤醒词不在本期 |
| 跨设备/云端同步记忆与计时器 | 不引入服务器 |
| 自定义工具 / 用户脚本 | 一律不做 |

| # | 问题 | 选项 | 推荐 | 影响 |

| OQ-5 | `pet_visibility(false)` 的前置条件？ | A 必须灵动岛已开（否则拒绝）；B 隐藏时自动开灵动岛；C 不校验 | **A** | 选 C 会出现"桌宠消失且无法恢复"的客诉——打开 App 也救不回来（F9） |
| OQ-6 | 隐藏桌宠时，语音对话是否继续？ | A 继续（胶囊保留）；B 一起停 | **A** | 选 B 更像"退出"，但和"躲起来"的语义不符 |
| OQ-7 | 高副作用工具要不要二次确认？ | A 都不要（快）；B 仅 `open_app` 首次要确认；C 每个 L2 都要 | **A**，二期再看 B | 加确认会让每次操作多一轮，语音体验明显变慢 |
| OQ-8 | 多开桌宠时工具作用于谁？ | A 发起本轮对话的实例；B 永远主实例（id=0）；C 全部实例 | **A**（拿不到则退化为 B） | `VoiceRuntime` 是进程单例（F7），不显式解析会作用到"最后创建的那只" |
| OQ-9 | 模型与思考模式 | 当前默认 `deepseek-chat`；官方文档现列 `deepseek-flash`/`deepseek-v4-pro`（F15）。是否切默认？工具轮是否显式 `thinking: disabled`？ | **切 `deepseek-flash` + 工具轮关思考**（延迟优先） | 不切可能遇到"模型不支持 tools"或延迟 8s+；关思考会改变现有聊天风格，需回归 |
| OQ-10 | 工具调用要不要给用户看？ | A 只进日志页；B 气泡显示"我做了 X"；C 语音说出来 | **A + 成功由模型顺口说** | B/C 会让每轮多一句废话 |
| OQ-11 | 工具开关放哪一层？ | A 全局一项（默认开）；B 按工具分项开关；C 无开关 | **A**，二期再拆 B | 分项开关要有设置页 UI 工作量 |
| OQ-12 | `remember` 与自动记忆抽取重复，会不会写两条？ | A 允许（工具写高 importance，抽取照旧）；B 工具写入时跳过本轮自动抽取 | **A**（有 `upsert` 去重兜底，F11） | 选 B 要改抽取时机，风险更大 |

## 10. 术语

| 术语 | 含义 |
| --- | --- |
